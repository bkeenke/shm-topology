# SHM Topology

Визуальный редактор связей SHM: событие → шаблон → отложенные задачи (spool) → TG-сообщения / письма.
Python 3 (только stdlib) + SQLite, без зависимостей.

## Запуск в Docker

    docker compose up -d --build     # http://127.0.0.1:8765
    docker compose logs -f           # логи
    docker compose down              # остановить

База лежит на хосте в `./data/topology.db` (примонтирована в контейнер как `/data`),
поэтому переживает пересборку и её можно открыть любым SQLite-клиентом.
Чтобы открыть доступ не только с этой машины — в `docker-compose.yml` замените
`"127.0.0.1:8765:8765"` на `"8765:8765"`.

## Запуск без Docker

    ./start.sh            # http://127.0.0.1:8765
    ./start.sh --port 9000 --db other.db

Переменные окружения: `SHM_TOPO_HOST`, `SHM_TOPO_PORT`, `SHM_TOPO_DB`.

## Импорт

«⇪ Импорт» → источники можно комбинировать:
- папка с шаблонами (`*.tpl`, `*.tpls`) — `.json` событий и `.sql` дамп из неё подхватываются сами;
- SQL-дамп (mysqldump) таблицы `templates` (`id`, `data`, `settings`); если в дампе есть таблица `events` —
  события берутся оттуда, JSON не нужен. Получить дамп:
  `mysqldump shm templates events > shm_tpl.sql`;
- JSON событий (массив из API SHM или `{"data": [...]}`).

При совпадении имён шаблон из SQL-дампа перекрывает файл `.tpl`. Галочка «Отдельная топология на каждое событие» — по одной схеме на
registered, payment, changed…

Что распознаётся автоматически:
- `settings.template_id` события → узел шаблона (category / title — подпись связи);
- `spool.add(...)` и `make_custom_event(...)` → связь «через 1 д» / «каждые 10 мин» / «custom event», рекурсивно
  по цепочке. `template_id`, `delayed`, `period` могут быть литералом или переменной
  (`{{ spool_template_id = 'X' }} … template_id = spool_template_id`) — значение подставляется из файла,
  в том числе из переменных, заданных до `BLOCK`/`PROCESS` или ниже по файлу. Вычисляемая задержка
  (`DELAY = 1 + con div 10`) показывается как выражение;
- `telegram.send(sendMessage|sendPhoto …)` → карточка сообщения с текстом и кнопками;
- событие с `subject` или задача на транспорт `mail` → карточка письма (тема из события или `.tpls`);
- условия: для каждого сообщения и каждой задачи вычисляется, при каком `IF / ELSIF / ELSE / UNLESS`
  она срабатывает (с учётом вложенности и `BLOCK` → `PROCESS`), и переводится на русский:
  `us.status == 'BLOCK'` → «услуга заблокирована», `us.status_before` → «до этого была …»,
  `!user.has_payments` → «нет платежей», `…telegram_bot.status != 'kicked'` → «бот не остановлен» и т.д.
  `STOP IF …` в начале шаблона → «Выполняется, если», остальные `STOP` → список остановок в панели.
  `spool.add` внутри `BLOCK`, чей `PROCESS` закомментирован, не показывается;
- `telegram.bot('telegram_bot', '/cmd', …)` → карточка «🤖 /cmd» с сообщениями из `<% CASE '/cmd' %>` шаблона бота
  (понимаются `tg_api( sendMessage = … )` и JSON-ответы `"sendMessage": {…}`); кнопки в CASE не раскрываются;
- получатель Telegram: профиль из `SHM_TOPO_USER_PROFILES` (по умолчанию `telegram_bot`) или без профиля →
  «👤 Пользователю», любой другой (`SUPPORT`, `VPN_PPL_Group`, …) → «👥 Группа <профиль>»;
- Happ push (`PushNotificationForm = { title, body, link_for_open }`) → карточка «📱 Push»; команды Happ,
  смена external squad, `set_settings`, `storage.save` → строка «⚙ действия» на карточке шаблона;
- публичные шаблоны (`allow_public` в `.tpls`/settings) выбираются в окне импорта; если в шаблоне есть
  `x = request.params.event` и ветки `x == '…'` (как в `remnawave_webhook`) — на каждую ветку свой узел-вход;
- технические проверки (`request.headers…`, `нет us.id`, счётчики) свёрнуты в «+ N тех. проверок»;
- `tpl.id('x').parse()` → связь «вызывает»; `http.get/post…` → список запросов в панели.

### Повторный импорт

В окне импорта «Куда → ↻ Обновить: <схема>» (или галочка «обновлять уже созданные схемы» при разбивке
по событиям). При обновлении:
- новые узлы и связи добавляются и ставятся рядом со связанными;
- позиции, заметки, ручные узлы и связи не трогаются;
- если узел правили руками, правка остаётся, а при изменении текста в шаблоне узел помечается
  «⚠ текст в шаблоне изменился» — в панели можно «Взять из шаблона» или «Оставить мой»;
- то, чего в шаблонах больше нет, не удаляется, а помечается «✖ больше нет в шаблоне».

Обновлять можно только схемы, созданные импортом этой версии (у них есть стабильные ключи узлов).
Исходники шаблонов сохраняются в библиотеку (таблица `templates`) и видны в панели узла.

## Управление

- колесо — зум, перетаскивание фона — сдвиг, перетаскивание узла — перемещение (позиция сохраняется);
- ● справа у узла — потянуть на другой узел, чтобы создать связь;
- клик по узлу — редактирование и подсветка всей цепочки; двойной клик по фону — заметка;
- `Del` — удалить выбранное, `F` — показать всё, `/` — поиск;
- ⧉ дублировать, ⇩ экспорт в JSON, «Загрузить из .json» — восстановить.

## База

`data/topology.db` (SQLite): `topologies`, `nodes`, `edges`, `templates`. Можно править и напрямую.
